# ES 人话（业务能读）

> 写 Executive Summary 前读本文。键名、顺序、目录编号仍受 [04-report.md](../phases/04-report.md) #27 和 `check-report-skeleton.py` 锁定。  
> 样例：[case-hoppercap1tps-20260915.md](../examples/case-hoppercap1tps-20260915.md)。**不回改 gold。**

ES 是业务第一屏。内部黑话放括号或六键末尾，不要开篇就写给 Agent 回归用的代号。

**不要**把整份 Phase 4 丢给外部「说人话」改写 skill：它会保住 `CS` / `3a` / `PPS`，解决不了读者问题。

## 两层（同一节，不要附录）

1. **导语 3～5 句（给业务）**  
   只回答：涨了还是掉了、是不是从低点回升、谁贡献、像谁的问题、机构查价有没有大动、下一步问谁、还没核实。  
   必须是六键的转述，**不得新编事实**。

2. **六键（给内部，键名逐字）**  
   `异动` / `结构` / `主因` / `并列` / `已排除` / `后续动作`。  
   正文用人话；`parent`、`SID`、`CS`、`3a` 等放括号。  
   **后续动作** 先写「问谁、问什么」，末尾仍须 `目录 **C2**` 这类编号（[es-cause-catalog.md](./es-cause-catalog.md)）。

## 导语禁止出现

`parent`、`WoW`、`Z`、`SID`、`验证 B`、单独的 `CS`/`C`/`S`（定责缩写）、`SS`、`3a`、`CSA`、`PPS`、`Δpp`、`目录 C2`。

供应商用业务名（Expedia，不要开篇写 `116-EPS`）。数字可保留（+52.2%、+68.6%）。

## 机构查价必须写

机构查价量 `|WoW|>10%` → **必须**进导语或 **并列**（或两处都写）。写成「渠道向我们查价的次数 ±X%」。  
禁止为了人话把它删掉；也禁止用它盖掉真正的主因（例如某供应商查价不动、产量翻倍）。

## 人话对照（导语 / 六键正文）

| 内部 | 业务怎么写 |
|------|------------|
| parent / 子账号 | 同一客户下的账号；点名 HopperCap1TPS / DC |
| SID / 116-EPS | 供应商常用名（Expedia） |
| 定责 CS | 「这条渠道 × 这家供应商」对接链路自己的变化 |
| 定责 C | 渠道侧 |
| 定责 S | 供应商全网 / 多数客户同一家都在动 |
| 验证 B | 别的客户在同一家供应商上 |
| SS | 这家供应商的查价 |
| 机构 PPS | 渠道向我们查价的次数 |
| 3a / CSA 开房 | 内部有没有给这家供应商重新开资源 |
| 限流 / L2L / CBD | 六键「已排除」里用短白话，括号可留原词 |

## Agent 禁止

- ❌ 导语堆 `parent WoW Z SID 验证 B CS`
- ❌ 删掉机构查价 `|WoW|>10%` 只为了好读
- ❌ 导语写「不像渠道放量」却不提机构查价其实在暴增（或反过来）
- ❌ 六键改名（`主因（倾向 S）`、`并列 C`）
- ❌ 后续动作去掉「目录 **A#**」
- ❌ 人话里新编产量、配置或定责
