# ES 人话（业务能读）

> 写 Executive Summary 前读本文。键名、顺序、目录编号仍受 [04-report.md](../phases/04-report.md) #27 和 `check-report-skeleton.py` 锁定。  
> 样例思路见 HopperCap / SnapTravel2B 成品报告 ES。**不回改 gold。**

ES 是业务第一屏。内部黑话放括号或六键末尾，不要开篇就写给 Agent 回归用的代号。

**不要**把整份 Phase 4 丢给外部「说人话」改写 skill：它会保住 `CS` / `3a` / `PPS`，解决不了读者问题。

## 两层（同一节，不要附录）

1. **导语 3～5 句（给业务）**  
   只按这个顺序答：  
   ① 涨了还是掉了、大概多少；  
   ② 掉/涨在哪（最多两层：账号或国家/供应商，不要一次塞 parent→账号→供应商→酒店→子账号）；  
   ③ 像谁的问题（渠道 / 我们配置 / 供应商全网）；  
   ④ 查价或在线有没有大动（该写则写）；  
   ⑤ 下一步问谁、还没核实。  
   必须是六键的转述，**不得新编事实**。

2. **六键（给内部，键名逐字）**  
   `异动` / `结构` / `主因` / `并列` / `已排除` / `后续动作`。  
   正文用人话；`parent`、`SID`、`CS`、`3a` 等放括号或干脆不写。  
   每键尽量 **一句**；数字保留，解释词要短。

## 导语禁止出现

`parent`、`WoW`、`Z`、`SID`、`验证 B`、单独的 `CS`/`C`/`S`（定责缩写）、`SS`、`3a`、`CSA`、`PPS`、`Δpp`、`目录 C2`、`查验比`（改写成「验价变多/变少、更好核价/更难核价」）、账号纯数字（改写成「Expedia 下的主产账号」或业务能懂的称呼）。

供应商用业务名（Expedia，不要开篇写 `116-EPS`）。数字可保留（+52.2%、少了约 1,500 单）。

## 机构查价必须写

机构查价量 `|WoW|>10%` → **必须**进导语或 **并列**（或两处都写）。写成「渠道向我们查价的次数 ±X%」。  
在线日均少 **≥1.5h**（过异动）→ **必须**进导语或 **并列**。写成「周末有短时下线 / 在线少了约 X 小时」，并写清 **只解释查价**。  
禁止为了人话把它删掉；也禁止用它盖掉真正的主因（例如某供应商查价不动、产量翻倍）。

## 六键怎么写（业务优先）

| 键 | 写法 | 禁止 |
|----|------|------|
| **异动** | 一句：多少→多少或大约涨/跌多少 | 堆评分公式、Z、等级全称 |
| **结构** | 一句：主要掉/涨在哪（国家/供应商/账号最多各点一个） | parent→SID→酒店→账号连环 |
| **主因** | 一句人话倾向；内部定责缩写可放句末括号 | 开篇写 `2b`/`验证 B`/`C1` |
| **并列** | 最多两点放大因素 | 与主因重复讲同一件事 |
| **已排除** | **必须留这一键**；**只写一句**，挑业务最容易误判的 1～2 点（如「不是掉线」「不是限流」「不是全网一起涨」） | 列成黑话清单（L2L/Configuration/Δpp/未过线） |
| **后续动作** | **先写**问谁、问什么（业务句）。末尾只留极简回归标记：`目录 **A3**`（最多再加一个 `+ **C1**`）。详细「现象→可能原因」写在 **§6 后续动作**，不要堆在 ES | ES 里写 `→ 供应商侧为主…`、`禁止写成已确认`、长串目录解释 |

**「已排除」为什么还要：** 业务也会顺着错误方向追（以为掉线、以为限流）。留一句人话挡错路；细清单留给正文证据对照，不进 ES。

**目录编号为什么还要极简标记：** checker / 回归要对上 [es-cause-catalog.md](./es-cause-catalog.md)。业务不必读懂 `A3`；所以 **禁止**在 ES 展开箭头说明，只保留末尾短标记。

## 人话对照（导语 / 六键正文）

| 内部 | 业务怎么写 |
|------|------------|
| parent / 子账号 | 同一客户下的账号；点名 HopperCap1TPS / DC |
| SID / 116-EPS | 供应商常用名（Expedia） |
| 账号 283 | Expedia 下的主产账号（或业务已知称呼）；禁止只丢数字 |
| 定责 CS | 「这条渠道 × 这家供应商」对接链路自己的变化 |
| 定责 C | 渠道侧 |
| 定责 S | 供应商全网 / 多数客户同一家都在动 |
| 验证 B | 别的客户在同一家供应商上 |
| SS | 这家供应商的查价 |
| 机构 PPS | 渠道向我们查价的次数 |
| 验价↑ / 查验比↓ | 验价变多、更好核到价 |
| 验价↓ / 查验比↑ | 验价变少、更难核到价 |
| 3a / CSA 开房 | 内部有没有给这家供应商重新开资源 |
| 限流 / L2L / CBD | 「已排除」里用短白话，括号可留原词 |

## 合格 / 不合格示例（后续动作）

**合格：**
`对内确认 10/22 机构兜底是否按计划，并盯美国同日预订。目录 **A3**`

**不合格：**
`（目录 **C1**+**C3** → 供应商侧为主、账号放大为并列；禁止写成已确认）`

## Agent 禁止

- ❌ 导语堆 `parent WoW Z SID 验证 B CS`
- ❌ 导语一层里塞超过两个结构层级
- ❌ 删掉机构查价 `|WoW|>10%` 只为了好读
- ❌ 导语写「不像渠道放量」却不提机构查价其实在暴增（或反过来）
- ❌ 在线已过 1.5h 异动，导语和并列都不提下线/在线缩短
- ❌ 六键改名（`主因（倾向 S）`、`并列 C`）
- ❌ **已排除** 写成三条以上黑话清单
- ❌ **后续动作** 在 ES 展开 `→` 原因链或「禁止写成已确认」
- ❌ 后续动作去掉末尾 `目录 **A#**` 极简标记
- ❌ 人话里新编产量、配置或定责
