# Phase 3d：A + B + C 综合判断规则

> Phase 2b 定责方向 + Phase 3 三条证据线合成结论。  
> 前置：[config-search-precheck-mapping.md](./config-search-precheck-mapping.md)、[accuracy-issue-mapping.md](./accuracy-issue-mapping.md)

## 1. 三条证据线（边界）

| 线 | 代号 | 回答什么 | 可对接 | **禁止** |
|----|------|---------|--------|---------|
| 配置 | **A** | 窗口内有没有内部配置变更 | QPS、有价率、验价量、查验比 | 准确率 |
| 查价/竞争力 | **B** | 有价率、查验比哪维变了 | 同上 + 在线/限流辅助表 | 准确率 |
| 准确率 | **C** | 验价技术质量哪维坏了 | issue_type → issue_id | 配置/限流/在线表 |
| 外部日历 | **D** | Top 国是否有节假日 | 2c 国（C=`4_Country`；S/CS=`5_SID+Country`）+ 营销日历 | **替代 A/B 定责**；A/B 已强时 **不查** |

**硬规则：配置变更不影响验价准确率。A 与 C 不得交叉定责。D 为 Dida 全局表，禁止与 client 产量交叉。**

## 2. 合成总流程

```
输入：Phase 1（BKS 异动）、Phase 2b（C/Dida | S | CS）、Phase 2c（Top 维）
  │
  ├─ 3a 配置清单（14 行）+ 配置→指标预期对照
  ├─ 3b 查价归因（有价率 WoW、查验比 WoW，同维 as 2c Top）
  ├─ 3c 准确率（每案 01-total；\|Δpp\|≥5 才维+issue）
  ├─ 3d 外部日历 D（§5 触发时；A/B 已强则跳过）
  │
  ▼
综合表：每条假设 × 证据 × 强度 × 结论
  │
  ▼
输出：已确认 / 倾向 / 待验证 / 移交报告收口
```

**执行顺序（供给/竞争力）：** 有价率 → 查验比 → QPS/限流/在线 → **D 外部日历（触发时）**  
**限流/缓存：** **结构 SID 必出数**（锁定或占 \|ΔBKS\|≥10%）→ `rate-limit-lite`；SS 有价/请求 \|WoW\|>10% 只定解读档。**跌方向**见下表序号 5/5b/3/3b；**涨方向或请求↓产量↑** 仅报数；**未过 10%** 仍出表作排除（§5.10）。  
**准确率：** 独立并行。每案 `01-total`；`\|Δpp\| ≥ 5` 才维+issue。未过线 = 已探测未启动。

## 3. 置信度定义

| 等级 | 含义 | 写入报告 |
|------|------|---------|
| **已确认** | A 有关键配置 + B 指标变化 **与预期一致** + 同维 BKS 贡献显著 | 「已确认根因」 |
| **倾向** | 2–3 条证据同向，缺一项或幅度偏弱 | 「倾向 XXX，建议验证」 |
| **待验证** | 单一线索或指标 inconclusive | 「待验证假设」 |
| **数据无法解释** | A/B/C 均无法解释 BKS 主因 | 报告收口：查 [es-cause-catalog.md](./es-cause-catalog.md)（可能原因，禁止已确认） |

**禁止：** 弱信号（**小幅调价且 B 不同向**、**LCDH 新增酒店（击穿兜底名单）且变更 hotel 零单**）单独写成「已确认」。机构 **C/CBD 加价** + 查验比同向 **可以** 作主因。

## 4. 按 Phase 2b 方向的合成规则

### 4.1 2b = **C 或 Dida**（门 2 已写死：家数≥70% 且无单 SID≥50%）

**目标：** 把「C 或 Dida」拆成 **Dida（配置/竞争力）** vs **C（渠道侧）**。

| 序号 | 若观察到… | 则… | 强度 |
|------|----------|-----|------|
| 1 | A：CS/C **关房** + 时间吻合 + B：**有价率↓**（同 scope）+ BKS↓ | **倾向 Dida（配置-关房）** | 强 |
| 1b | A：**L2L 升级或降级**（`last_level`（LAG(level)）≠ `level`）+ BKS 同向 | **倾向 Dida（面纱）**；可与 CS 结构并列。**禁止标弱** | 中～强 |
| 2 | A：**C Bottom / Configuration** 变更 + B：机构级 **查验比↓** 或验价量↓ + BKS↓ | **倾向 Dida（配置-竞争力）** | 强～中 |
| 3 | A：**加价**（**C / CBD** / CS / C Bottom）+ B：查验比↑或验价↓ + BKS↓ | **Dida（价劣）**，可作主因。**禁止标弱**。涨产对称：降价 + 查验比↓/验价↑ | **强** |
| 3b | A：加价/降价/关房但 **B 方向反了** | **inconclusive / 未拉回**。禁止「已确认」，也禁止「14 类无」 | — |
| 4 | A：过 **「倾向 C」出门禁**（机构无加价/关房/等级变/PPS；对应操作的 B 未兑现）+ BKS↓ | **倾向 C** → 报告收口。出门禁见 Phase 3 #26（按操作选行，不钉单边 %） | 中 |
| 5 | A：无 + B：**DidaBiz QPS↓>10%** + 在线时长日均 **↓≥1.5h** + **邮件解析** 有上下线动作 | **倾向 C（渠道下线/在线）** → **只解释查价↓**（§online-hours §2） | 中～强 |
| 5b | A：无 + B：QPS↓>10% + 在线 **↓≥1.5h** 但 **仅数据库分析** source | **辅助参考**，写「疑似下线，待渠道确认」 | 弱 |
| 5c | 在线↓ + 查价↓ 但 **BKS↑**（转化↑） | 在线 **只解释查价段**；产量由 **转化/S** 驱动，**不得**用在线定责产量 | — |
| 6 | A：**LCDH 新增酒店（击穿兜底名单）** + BKS↓ 但 **hotel_bks≈0** | **弱 / inconclusive**，不单定责 | 弱 |
| 6b | A：**SH 批量**（n≥10）+ 机构 BKS 大动但 **hotel_bks≈0** | **弱 / inconclusive**，禁止 SH 定责（平台改房未打到本 client） | 弱 |
| 7 | C 线：准确率 **↓≥5pp** + issue **Timeout/30xx↑** | **并列：技术指标问题**（不推翻 Dida/C，独立一条） | 中 |

**报告收口触发（4）：** ES 查 [es-cause-catalog.md](./es-cause-catalog.md)。D 组（加价/关房/L2L）已兑现 → 对内，禁止套 B2 问渠道。无强配置才可按目录 B2 问看不见的渠道操作（禁止写成已确认）。

### 4.2 2b = **CS**（仅 focus client × Top supplier 组合降）

**目标：** 确认是 **CS 链路配置** vs **该 supplier 竞争力/渠道对接** vs **技术指标**。

| 序号 | 若观察到… | 则… | 强度 |
|------|----------|-----|------|
| 1 | A：**CS 关房** + B：该 CS scope **SS 有价↓/量↓** + BKS↓ | **倾向 Dida（CS 配置）** | 强 |
| 1b | A：**L2L 升级或降级**（机构级面纱） | **并列 Dida（面纱）**；不替代 CS 结构。**禁止标弱** | 中～强 |
| 2 | A：**CS 无** + B：该 supplier **查验比↓**（同维）+ 全平台该 supplier rp 平/升、仅本 client 跌 | **倾向 CS 独有：竞争力或对接**（非 wolf 关房；若同时有 L2L 升降级则与 1b 并列） | 中～强 |
| 3 | A：**CS 加价** + B：**查验比↑** + BKS↓ | **倾向 Dida（CS 价劣）** | 中 |
| 4 | A：CS 无 + B：有价率正常 + 查验比正常 + BKS↓ | **待验证 / C 或外部** | 待验证 |
| 5 | B：**SS 有价率↓** + **SS限流率 WoW↑**（`rate-limit-lite`），A：CS/S **无关房** | **倾向限流**（非配置关房） | 中 |
| 5b | B：**SS 请求量↓** + **缓存命中率 WoW↑**，A：无关房 | **倾向缓存替代实发** | 中 |
| 6 | C：准确率 **↓≥5pp** + issue 4002/4003↑ | **倾向渠道数据修正** → 报告收口 | 中 |

**典型：HBGPKG×Meituan** — 2 平台 Meituan 平、HBGPKG 独降 + CS 无 → 走 **序号 2**，查 SS 查验比/US 维，不是继续盯 CS 配置。

## 5. A × B 对照速查（配置预期是否兑现）

配置变更后，在 **同一 level、同一 scope、同一时间窗** 查 B：

| 配置类型 | 预期 B 指标变化 | 若 BKS↓ 且一致 | 若 BKS↓ 但 B 不一致 |
|---------|----------------|---------------|-------------------|
| C/CS **关房** | 有价率↓（C→DidaBiz；CS→SS） | 强支持 Dida | inconclusive，查别因 |
| C/**CBD**/CS/S **加价** | 验价量↓，查验比↑ | **强**支持 Dida 价劣（与关房同等） | 可能竞品/渠道仍不验 |
| **降价** | 验价量↑，查验比↓ | 降价未拉回 → 仍无优势 | 序号见 CS-2 |
| CDH 关房（多 hotel） | 对应 hotel 无价↑ | 强（看 hotel_bks） | 关错 hotel / 弱 |
| Configuration QPS | DidaBiz QPS↓ | 强 | — |
| **L2L 升级/降级** | QPS 可不变；转化/产量同向 | **中～强 Dida 面纱**，**禁止标弱** | 仍写主因候选，并列查 CS/价劣；不得改成弱 |
| 无配置 | — | 走 B 单独解读 | 走报告收口 |

完整预期表：[config-search-precheck-mapping.md](./config-search-precheck-mapping.md)

## 6. C 线（准确率）独立解读

**仅当 SQL2 显示准确率 WoW 明显异常时启动。**

| issue_type 升 | 常见 issue_id | 报告结论类型 | 与 A/B 关系 |
|--------------|--------------|-------------|------------|
| Timeout (10) | 1001, 1003 | 接口/性能问题 | **并列假设**，不解释 BKS 主因时用 |
| NoRoom (20) | 2001–2006 | 验价失败分类 | **不**回去查 wolf 配置 |
| PriceChanged (30) | 3001–3015 | 验价同步/政策不一致 | 技术线 |
| Other (40) | 4002, 4003 | **渠道侧数据** → 报告收口 | 独立 |

**BKS 降 + 查验比正常 + 准确率大幅↓：** 报告写「产量受损可能含验价失败」，主因仍先查 A/B；C 作 **并列**。

## 7. 并列假设（必须允许）

规则：[external-events-mapping.md](./external-events-mapping.md) · D2 rubric 完整示例 **§10.7**

| 观察到 | BKS | 合成 |
|--------|-----|------|

| Top 国 + **Top30 HOLIDAY** 重叠 + D2 **中** | 跌/涨 | **并列**节后/假前效应，**倾向**；仍禁止 ±X% |

| A/B 已达「强」（含 S + 验证 B 平台共向） | 任意 | **未查 D**；不改 A/B 主因 |

## 11. 涨产与 2b/3b 衔接（2026-08-14）

| 阶段 | 规则 |
|------|------|
| **2b** | 涨产镜像见 [responsibility-model.md](../responsibility-model.md)。Top S 多 client 同涨 → **S 成分**；客户涨幅 >> 大盘 → **「C/S 并列待 3b」**，不写 C 主因 |
| **3b 强制** | **2b = C/Dida 或涨产待区分** → 必须先有 **机构级** B 线（`00-client-total` 或 funnel 加总 + client precheck），再写 SS 补充 |
| **3d** | 「C 主因 / 已排除 Dida」需：**3a = 14/14** + 机构级 B 线完整；否则最高 **「倾向」** |

**涨产 + 查价量降 + 产量升：** 报告写「转化/漏斗变化（验价量 vs 查价量背离）」；不得仅用 SS 层推断机构结论。

## 12. Agent 禁止

- ❌ 用配置解释准确率变化

- ❌ 仅 14 类有/无就定责，不跑 3b
